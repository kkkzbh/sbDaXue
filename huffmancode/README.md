# huffmancode · 大一下数据结构课程设计

这是我在 **2024 年大一下学期《数据结构》课程设计**中完成的文件压缩与解压项目，使用 **C++20** 编写，运行界面为 **Windows 交互式控制台**。

课设以**哈夫曼编码（Huffman Coding）**为核心：从文件字节频率统计开始，完成哈夫曼树构建、编码表生成、压缩文件写入与解码还原。围绕这一流程，项目还实现了堆、哈希表和循环缓冲区，并扩展了 **RLE、LZ77、LZ77 + Huffman 组合压缩**，通过具体程序练习数据结构、算法和文件处理之间的配合。

## 项目做了什么

| 功能 | 实现内容 | 对应模块 |
| --- | --- | --- |
| 哈夫曼压缩与解压 | 统计字节频率、构建哈夫曼树、生成前缀编码、保存解码表、打包编码位流并还原文件 | `fun`、`huftree`、`statistics`、`hufio` |
| RLE 压缩与解压 | 分别处理连续重复字节和连续非重复字节，使用块标记记录数据 | `rle` |
| LZ77 压缩与解压 | 在滑动窗口中寻找重复子串，使用三元组表示匹配结果，并按窗口内容还原 | `lz77` |
| 组合压缩与解压 | 先进行 LZ77 编码，再对三元组做哈夫曼编码；源码中命名为 `deflate` | `deflate` |
| 自定义基础数据结构 | 实现可指定比较规则的堆、带扩容和查找的哈希表、循环字符串缓冲区 | `priority_queue`、`map`、`hash`、`string_buffer` |
| 控制台交互 | 菜单选择、输入与输出路径录入、结果提示、返回菜单、退出程序 | `menu` |
| 动态显示与计时 | 滚动欢迎文字、时钟、哈夫曼处理进度提示、操作耗时显示 | `menu`、`clock`、`time` |

这些算法直接由项目源码实现。压缩与解压通过同一套菜单调用，使用者可以指定输入文件和输出文件。

## 哈夫曼编码的实现

### 1. 按字节统计频率

`statistics.cpp` 中的 `word_frequency()` 以二进制方式读取文件，统计各个字节值的出现次数，作为叶子结点的权值。

这里处理的是文件的**字节序列**。例如，UTF-8 中文文本中的一个汉字通常包含多个字节，程序会分别统计这些字节，不进行分词或字符编码转换。

### 2. 用最小堆构建哈夫曼树

`huftree.cpp` 将出现过的字节建立为叶子结点，并把“权值、结点下标”放入自写的 `priority_queue`。通过指定比较规则，这里使用最小堆：

1. 取出权值最小的两个结点。
2. 创建父结点，权值为两个子结点的权值之和。
3. 记录父子关系，将父结点放回堆中。
4. 重复合并，直到堆中只剩下根结点。

树的结点保存在 `std::vector` 中，父结点、左孩子和右孩子通过下标关联。这部分对应课上关于二叉树、堆和贪心构造的知识。

### 3. 遍历树并生成编码表

`hufcode::create()` 使用深度优先遍历与回溯生成编码：向左走追加 `0`，向右走追加 `1`，到达叶子时记录路径。

程序同时建立两种映射：

- **字节 → 编码串**：使用数组保存，供压缩时查找。
- **编码串 → 字节**：使用自写哈希表保存，供解压时查找。

哈夫曼编码是一种前缀编码，完整码字不会成为另一个码字的前缀，因此可以逐位识别码字边界。

例如，假设 `A`、`B`、`C` 分别出现 5、2、1 次，一组合法编码为：

| 字节 | 次数 | 编码 |
| --- | ---: | --- |
| A | 5 | `0` |
| B | 2 | `11` |
| C | 1 | `10` |

这 8 个字节原本占 64 位，编码数据部分可用 `5×1 + 2×2 + 1×2 = 11` 位表示。实际文件还需要保存解码表、块计数等信息，因此文件大小还受这些额外数据影响，尤其是小文件。

### 4. 将编码写入压缩文件

当前源码在 `utility.h` 中启用了 `OPTIMISE`。对应的哈夫曼压缩流程使用 `string_buffer` 循环缓冲区，逐步接收编码串，并将位序列打包成整数块写出。

默认实现使用 `8 × sizeof(int)` 位作为打包单位；缓冲区转换函数按 32 位处理，对应项目目标 Windows 环境中的 32 位 `int`。不足一个整数块的尾部另外保存有效位数。

默认哈夫曼文件的逻辑结构为：

```text
解码哈希表 → 完整整数块数量 → 编码数据块 → 可选尾块（有效位数 + 数据）
```

编码数据先写入工作目录中的 `buff`，随后与解码表、计数等信息合并为用户指定的输出文件。

### 5. 读取编码并还原文件

解压函数 `depress()` 先读取文件内保存的解码表，再将整数块展开为位序列。程序逐步累积码字，通过哈希表查找对应字节，匹配成功后写入输出文件并继续解码。

这一过程把频率统计、建树、编码、序列化、位运算和文件恢复串成了完整的处理流程。

```mermaid
flowchart LR
    A[原始文件] --> B[统计字节频率]
    B --> C[最小堆构建哈夫曼树]
    C --> D[DFS 生成编码表]
    D --> E[编码并打包位流]
    E --> F[保存解码表和编码数据]
    F --> G[读取解码表并逐位匹配]
    G --> H[还原文件]
```

## 扩展算法

### RLE：游程编码

`rle.cpp` 使用连续相同字节的重复次数表示重复数据。例如，概念上可以将 `AAAAA` 表示为“5 个 A”。

实现区分两类数据块：

- **重复块**：记录长度和一个字节值。
- **非重复块**：记录长度和整段原始字节，减少逐个记录“1 次出现”带来的开销。

长度字段使用一个字节，最高位用于区分块类型。当前实现会先把输入文件读入内存，再生成这些块；长块的长度处理仍存在限制，详见后面的使用边界。

### LZ77：滑动窗口与重复子串

`lz77.cpp` 使用已经处理过的数据构成搜索窗口，在窗口中寻找与待处理数据相同的子串。当前参数为：

| 参数 | 数值 |
| --- | ---: |
| 搜索窗口 `window_length` | 128 字节 |
| 待处理缓冲区 `buffer_length` | 512 字节 |

匹配结果表示为三元组：

```text
（匹配串在当前窗口中的起始下标，匹配长度，后续字节）
```

三元组类型为 `std::tuple<uint16, uint16, char>`。程序通过字符串哈希计算子串特征，在窗口中查找匹配；输出一个三元组后，更新搜索窗口和待处理缓冲区。解压时读取三元组，从窗口复制对应片段，再补上后续字节。

这部分主要练习滑动窗口、字符串匹配、哈希计算，以及压缩端和解压端之间的状态同步。

### Deflate 模块：LZ77 + Huffman 组合压缩

`deflate.cpp` 先调用 LZ77 得到三元组序列，再统计各个三元组的出现次数，并以**整个三元组**为编码对象建立哈夫曼树。

```text
压缩：原始文件 → LZ77 三元组 → 三元组频率统计 → Huffman 编码 → 输出文件
解压：压缩文件 → Huffman 解码 → LZ77 三元组 → 窗口还原 → 输出文件
```

该模块展示了字典压缩与统计编码相结合的思路，处理过程中使用 `buff` 和 `buff2` 两个中间文件。

**这里的 `deflate` 是课设中的自定义组合实现，采用项目自己的二进制文件格式。它与 ZIP、gzip、zlib 文件格式不互通。**

## 自写数据结构与实现练习

| 结构或技术 | 在项目中的用途 |
| --- | --- |
| 堆 `priority_queue` | 提供建堆、插入、取堆顶和删除堆顶操作，用于选择两个最小权值结点 |
| 哈希表 `map` | 按桶保存键值对，提供插入、查找、遍历和扩容；保存解码表及三元组频率 |
| 哈希函数 `hash` | 为字符串与 LZ77 三元组计算哈希值 |
| 数组与顺序存储 | 保存字节频率、编码表和树结点，通过下标连接树结构 |
| 深度优先遍历与回溯 | 根据根到叶子的路径生成哈夫曼编码 |
| 循环缓冲区 `string_buffer` | 暂存 `0`、`1` 编码字符，支持追加、消费、遍历和整数转换 |
| 二进制文件读写 | 保存和恢复编码表、树结点、三元组及打包后的编码数据 |
| C++20 模板与 Concepts | 为通用堆、哈希表等组件表达类型约束 |
| 线程与互斥锁 | 支持菜单刷新、滚动文字与哈夫曼进度显示 |

其中，项目里的 `map` 采用哈希表结构，功能定位接近 `std::unordered_map`。`string_buffer` 中保存的是编码字符，输出时再转换成位打包的数据块。

源码还包含两项编译期实验开关，定义位置为 `utility.h`：

| 开关 | 当前状态 | 作用 |
| --- | --- | --- |
| `OPTIMISE` | 启用 | 哈夫曼流程使用循环缓冲区分段处理编码数据，并在解码过程中增量计算哈希值 |
| `O2` | 关闭 | 为组合压缩提供保存树并沿树解码的实现；默认组合压缩保存解码哈希表 |

`O2` 是项目内的预处理宏名称。切换这些宏会影响相关编码与文件读写流程，压缩和解压应使用相同的构建配置。

## 构建与运行

### 环境要求

- Windows：源码使用 `windows.h`、`conio.h`、`_getch()` 和 Windows 控制台 API。
- 支持 C++20 及 `std::format` 的 C++ 编译器与标准库。
- CMake 3.28 或以上版本。

下面以安装了 C++ 桌面开发组件和 Windows SDK 的 Visual Studio 2022 为例。源码包含中文文本，命令中使用 `/utf-8` 指定源码与执行字符集。

### 获取源码并编译

在 PowerShell 中执行：

```powershell
git clone https://github.com/kkkzbh/huffmancode.git
cd huffmancode
cmake -S . -B build -G "Visual Studio 17 2022" -A x64 -DCMAKE_CXX_FLAGS="/utf-8"
cmake --build build --config Release
.\build\Release\huffmancode.exe
```

也可以通过支持 CMake 的 IDE 打开项目，并配置 Windows C++ 工具链。Windows 构建与运行尚待实机验证。

### 菜单操作

| 按键 | 操作 |
| --- | --- |
| `1` | 哈夫曼压缩 |
| `2` | 哈夫曼解压 |
| `3` | RLE 压缩 |
| `4` | RLE 解压 |
| `5` | LZ77 压缩 |
| `6` | LZ77 解压 |
| `7` | LZ77 + Huffman 组合压缩 |
| `8` | 组合解压 |
| `0` / `Esc` | 退出 |

选定操作后，依次输入源文件路径和输出文件路径。程序完成操作后会提示输出位置并显示耗时，按回车返回菜单。哈夫曼流程额外提供阶段进度显示。

例如，使用哈夫曼压缩并还原文件：

1. 准备 `C:\huffman-demo\input.txt`。
2. 按 `1`，输入源路径，再输入 `C:\huffman-demo\input.huf` 作为压缩结果路径。
3. 按 `2`，输入压缩结果路径，再输入 `C:\huffman-demo\restored.txt`。
4. 比较原始文件与还原文件的内容。

`.huf` 是示例文件名后缀，程序根据菜单中选择的算法处理文件。压缩与解压操作需要成对选择。路径通过 `std::cin >>` 读取，输入路径应避免包含空格，输出目录需预先存在。

可以用 PowerShell 比较一次往返处理前后的 SHA-256：

```powershell
$originalHash = (Get-FileHash C:\huffman-demo\input.txt -Algorithm SHA256).Hash
$restoredHash = (Get-FileHash C:\huffman-demo\restored.txt -Algorithm SHA256).Hash
$originalHash -eq $restoredHash
```

结果为 `True` 表示这次样例的原始文件与还原文件哈希一致。仓库目前没有自动化测试或统一的性能基准数据。

## 使用边界

这个仓库用于保存和展示大一下数据结构课设的实现，阅读与运行时需要结合原始代码的边界：

- **平台与文件格式**：目标运行环境为 Windows；文件中直接写入了部分整数、三元组或结点的内存表示，读写依赖编译器、类型布局与构建配置，尚未定义跨平台的统一格式。
- **工作目录**：哈夫曼与组合压缩会使用固定名称的 `buff`、`buff2` 中间文件；在单独的工作目录中运行，并为输入文件、输出文件和中间文件使用不同名称。同一目录应一次运行一个实例。
- **边界输入**：空文件、仅含一种字节的文件，以及很长的 RLE 数据块等仍需完善处理。RLE 长度字段最高位承担标记作用，当前编码流程尚未按该字段的容量拆分所有长块。
- **压缩效果**：文件内需要保存解码信息；小文件、重复度低的数据或已经压缩过的数据，输出可能更大。菜单显示的是处理耗时，仓库没有给出压缩率或速度的量化承诺。

项目的主要学习价值是完整实践“数据结构 → 编码算法 → 文件存储 → 解码还原”，并通过多个算法观察不同的数据表示方式。
