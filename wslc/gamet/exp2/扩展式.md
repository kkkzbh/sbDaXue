# 扩展式博弈设计说明书

## 1. 模块概览
- 目标：解析扩展式（博弈树）描述，生成完整策略空间，计算纯策略纳什均衡，并输出博弈树图像。
- 核心文件：`extensive_form.py` 提供数据结构、树遍历与均衡求解；`tree_demo.py` 负责命令行入口与批处理逻辑。
- 关键产物：控制台打印策略组合与均衡信息，`tree_output/` 中保存的 PNG 博弈树图像。

## 2. 程序结构
### 2.1 数据模型
- `TreeNode`：表示博弈树节点，包含节点类型（决策/终止）、所属参与者、可选行动及叶节点收益。
- `TreeAction`：决策节点上的单一行动，记录行动标签与指向子节点的引用。
- `ExtensiveFormGame`：封装标题、参与者顺序与根节点，提供策略枚举与均衡计算接口。
- `PlayerStrategy`：参与者的完全策略（每个决策节点的行动映射）。
- `StrategyProfile`：全体参与者策略组合与对应收益向量。

### 2.2 辅助方法
- `_pick()`：多语言字段提取工具，兼容中英文键名。
- `_setup_chinese_fonts()`：注册中文字体，保证图像文字显示。
- `_game_from_payload()` / `_parse_node()`：递归构建博弈树并执行结构合法性校验。

## 3. 数据流与关键步骤
1. **输入解析**：
   - 接受 JSON 字符串、文件路径或已解析字典。
   - `_parse_node` 递归创建 `TreeNode`，确保每个行动都指向子节点，叶节点收益长度与参与者数量一致。
2. **策略空间构造**：
   - `decision_nodes_by_player()` 统计每位参与者在博弈树中的决策节点。
   - `player_strategies()` 对每名参与者的所有决策节点行动做笛卡尔积，构成完全策略集。
3. **策略组合求值**：
   - `_resolve_path()` 根据策略组合从根节点沿行动遍历至终止节点，记录经过的路径。
   - `_evaluate_profile()` 返回终止节点的收益向量。
4. **均衡判定**：
   - `iter_strategy_profiles()` 枚举全部策略组合。
   - `pure_nash_equilibria()` 应用最佳响应检验，与正规式模块保持一致。
5. **博弈树绘制**：
   - `visualise_game_tree()` 依据节点深度分层布局，决策节点用蓝色圆角框展示参与者，终止节点显示收益。

## 4. 算法细节
- **复杂度**：策略空间大小受制于各参与者决策节点行动数量，整体复杂度 `O(Π|A_i|)`。
- **逆向推演**：当前均衡判定基于纳什概念；若需子博弈完美均衡，可在 `_resolve_path` 基础上加入逆向归纳模块。
- **默认行为**：若策略未显式指定某节点行动，遍历时默认选择该节点定义的第一个行动，确保策略映射总是完整。
- **边界检查**：
  - 未知参与者、空行动集、收益向量长度不匹配将立即抛出异常。
  - 支持单参与者树，若该参与者没有决策节点将生成包含“（无须行动）”的策略。

## 5. 可视化设计
- 图像尺寸默认 `12×8`，可通过 `figsize` 参数调整。
- 节点布局：自顶向下按深度分层，同层均匀分布横坐标。
- 决策节点：蓝色圆角框，显示决策者姓名。
- 终止节点：浅灰圆角框，内部显示收益向量（顺序与参与者列表一致）。
- 边标签：使用白色描边增强对比，避免与线条重叠。
- 底部说明：注明收益向量顺序，辅助解读。

## 6. 操作说明
### 6.1 基本运行
```bash
cd exp2/
python tree_demo.py entry_game
```
- 若未提供参数，将处理 `tree_input/` 中全部 JSON 文件。
- `--show` 选项开启交互式窗口以便现场讲解。
- `--output <path>` 可自定义图像输出位置（相对路径默认相对于 `tree_output/`）。

### 6.2 输入文件格式
```json
{
  "标题": "进入与威慑",
  "参与者": ["Alice", "Bob"],
  "根节点": {
    "类型": "decision",
    "参与者": "Alice",
    "行动": [
      {
        "名称": "进入",
        "子节点": {
          "类型": "decision",
          "参与者": "Bob",
          "行动": [
            {"名称": "接受", "子节点": {"类型": "terminal", "收益": [3, 1]}},
            {"名称": "惩罚", "子节点": {"类型": "terminal", "收益": [-1, -1]}}
          ]
        }
      },
      {
        "名称": "退出",
        "子节点": {"类型": "terminal", "收益": [1, 0]}
      }
    ]
  }
}
```
- 节点字段支持中英文，例如 `type`/`类型`、`player`/`参与者`。
- 每个行动必须包含 `子节点` 描述；终止节点的 `收益` 长度应等于参与者数。

### 6.3 输出与日志
- 图像文件：默认写入 `tree_output/<输入文件名>.png`。
- 控制台信息：
  - 参与者顺序与策略集（逐条列出每个策略的节点→行动映射）。
  - 全部策略组合的收益与是否纳什均衡。
  - 纯策略纳什均衡的策略配置与收益。

### 6.4 常见问题排查
- **输入路径错误**：确认 JSON 位于 `tree_input/` 或提供绝对路径。
- **节点类型报错**：检查是否拼写正确（`decision` / `terminal`）。
- **收益向量长度不符**：核对终止节点的数组长度是否与 `参与者` 列表一致。
- **图像显示不完整**：可调整 `figsize` 或手动修改布局参数。

## 7. 扩展建议

- 增加信息集合建模，支持不完美信息博弈。
- 引入逆向归纳法，标注子博弈完美均衡路径并在图像中高亮。
- 输出树形 JSON/Graphviz 格式，便于与其他分析工具对接。
- 提供策略敏感性分析，比较不同均衡之间的收益差异。
- 与战略式模块联动，实现从扩展式博弈自动推导其策略式表示。
