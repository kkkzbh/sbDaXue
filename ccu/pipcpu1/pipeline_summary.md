### 流水线 CPU 核心逻辑摘要

本文档概述了 `P_PipelineCPU.v` 中实现的五级流水线 MIPS CPU 的核心组件。

#### 1. 流水线阶段

CPU 被划分为五个独立的阶段，通过流水线寄存器进行分隔，以实现指令的并行处理。

*   **IF (取指令):**
    *   使用 `pc` (程序计数器) 寄存器中的地址，从 `P_InstructionMemory` 中获取下一条指令。
    *   计算 `pc_plus4` 以指向序列中的下一条指令。

*   **ID (译码):**
    *   对取来的指令进行译码，以确定控制信号。
    *   从 `P_Regfile`（寄存器堆）中读取源操作数。
    *   包含用于管理暂停（stall）的冒险检测单元。

*   **EX (执行):**
    *   执行指令所规定的计算，通常由 ALU（算术逻辑单元）完成。
    *   包含用于解决数据冒险的转发单元（Forwarding Unit）。
    *   计算分支目标地址。

*   **MEM (访存):**
    *   对于 `lw` (加载字) 和 `sw` (存储字) 指令，从 `P_DataMemory`（数据存储器）中读取数据或向其写入数据。
    *   对于 R 型指令，直接将 ALU 的计算结果传递到下一阶段。

*   **WB (写回):**
    *   将最终结果（可能来自存储器或 ALU）写回到 `P_Regfile` 中。

#### 2. 流水线寄存器

这些是由时钟驱动的寄存器，用于在指令从一个阶段流向下一个阶段时，保存其所需的数据和控制信号。它们是隔离各个阶段的关键，并且在每个时钟周期都会更新（除非流水线被暂停）。

*   `id_pc`, `id_inst` (位于 IF 和 ID 阶段之间)
*   `exe_pc`, `exe_op1`, `exe_op2`, `exe_inst`, 等 (位于 ID 和 EX 阶段之间)
*   `mem_pc`, `mem_alu_result`, `mem_dest`, 等 (位于 EX 和 MEM 阶段之间)
*   `wb_wdata`, `wb_dest`, `wb_reg_write` (位于 MEM 和 WB 阶段之间)

#### 3. 冒险检测单元

*   **位置:** ID (译码) 阶段
*   **目的:** 防止数据冒险，特别是"加载-使用"冒险（load-use hazard）。
*   **逻辑:** 它会检查处于 ID 阶段的指令是否想要读取一个寄存器，而这个寄存器恰好是正处于 EX 阶段的 `lw` 指令的目标寄存器 (即 `if (load_use_hazard)`)。
*   **动作:** 如果检测到冒险，该单元会激活 `stall` 信号。这会冻结 `pc` 和 IF/ID 流水线寄存器，从而在流水线中插入一个"气泡"（bubble，相当于一个 NOP 空操作），等待加载指令完成内存访问。

#### 4. 转发单元

*   **位置:** EX (执行) 阶段
*   **目的:** 在不暂停流水线的情况下，尽可能地解决数据冒险。它将后续阶段（MEM, WB）的结果提前传递回 EX 阶段，供 ALU "及时"使用。
*   **逻辑:**
    *   检查 EX 阶段当前指令的源寄存器（`exe_rs`, `exe_rt`）是否与流水线更下游指令的目标寄存器相匹配。
    *   **从 MEM 阶段转发:** `(exe_rs == mem_dest && mem_reg_write)` - 如果源寄存器与 MEM 阶段指令的目标寄存器匹配，就转发 `mem_alu_result`。
    *   **从 WB 阶段转发:** `(exe_rs == wb_dest && wb_reg_write)` - 如果源寄存器与 WB 阶段指令的目标寄存器匹配，就转发 `wb_wdata`。
*   **动作:** `exe_rs_fwd_val` 和 `exe_rt_fwd_val` 信号会选择正确的值（转发来的值或原始寄存器里的值）送给 ALU。这个逻辑同样适用于为 `sw` 指令提供要存储的数据。
